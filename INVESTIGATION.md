# NLE v1.0.1 — missing httpd investigation

## Summary

### Root cause

In v1.0.1, the rootme bootstrap (generated by `firmware/builder/build.sh`, commit `e796765` + `123595b`) writes the symlink `/bin/httpd → /bin/busybox2` to the persistent rootfs (mtdblock7) **unconditionally** at line 601, but the matching `cp /bin/busybox2 /tmp/1/bin/busybox2` line that puts the target binary onto the persistent rootfs is wrapped in the `if [ "$ENABLE_ROOT_ACCESS" = true ]` block (line 527–566). Default installs (the user's case — no `--enable-root-access`) skip the copy, so the symlink dangles after reboot. The nleapi init script then cannot launch httpd, and the upstream installer's URL-config fetch fails. A secondary mismatch — `httpd.monitrc` watches `/usr/sbin/httpd` while the init script launches `${BINDIR}/httpd` (= `/bin/httpd` per `/etc/init.d/functions`) — would have kept monit unhappy even after fixing the missing binary, because monit's `matching` pattern would never see the running process.

### Fix approach

Two-line change on branch `fix-missing-httpd-in-firmware`:

1. `firmware/builder/build.sh` — move `cp /bin/busybox2 /tmp/1/bin/busybox2` and its `chmod` out of the `ENABLE_ROOT_ACCESS` conditional, so every install ships busybox2 onto mtdblock7. The dropbear/autossh deps stay gated on root access.
2. `firmware/builder/deps/httpd.monitrc` — change `matching /usr/sbin/httpd` to `matching /bin/httpd` to agree with the init script's `BINDIR=/bin`.

The init script (`deps/nleapi`) and the symlink target (`build.sh` line 601) already agree on `/bin/httpd`; nothing there needs to change.

## Details

### Walk-through of the bug

`firmware/builder/build.sh` regenerates `/etc/init.d/rootme` inside the extracted initramfs every build. The relevant excerpt of the generated rootme (in v1.0.1) is:

```sh
mount /dev/mtdblock7 /tmp/1 -tjffs2

# ENABLE_ROOT_ACCESS block — SKIPPED on default builds
if [ "$ENABLE_ROOT_ACCESS" = true ]; then
  cp /bin/busybox2 /tmp/1/bin/busybox2   # <-- lives here in v1.0.1
  cp /bin/autossh /tmp/1/bin/autossh
  ...
fi

# Unconditional nleapi section
cp /tmp/nleapi/nleapi /tmp/1/etc/init.d/nleapi
cp /tmp/nleapi/httpd.monitrc /tmp/1/etc/monit.d/httpd.monitrc
...
ln -sf /bin/busybox2 /tmp/1/bin/httpd   # <-- depends on busybox2 being copied
```

On default builds the `cp busybox2` line is not emitted into the rootme script, but the `ln -sf` line is. So after reboot the persistent rootfs has `/bin/httpd → /bin/busybox2` and no `/bin/busybox2`. nleapi's `start-stop-daemon -a /bin/httpd` then has nothing to exec.

### Why the user's workaround works

The user drops a static busybox-with-httpd at `/usr/sbin/httpd` and runs `/etc/init.d/nleapi monit_start`. That works for two independent reasons:

1. They (separately) almost certainly placed or symlinked the binary so `/bin/httpd` also resolves — the workaround is widely shared and the typical recipe is to wget into `/usr/sbin/httpd` *and* `ln -sf` it into `/bin/httpd`. nleapi's init script then has something to exec.
2. Even if only `/usr/sbin/httpd` exists, monit (per the broken monitrc) thinks the daemon is running once the user manually invokes anything with `/usr/sbin/httpd` in its cmdline, so the alert clears.

### Hypotheses status

From `CLAUDE.md`, in priority order:

1. **"BusyBox in the 4.3.3 cpio doesn't have httpd compiled in."** — Confirmed for `/bin/busybox`. NOT confirmed for `/bin/busybox2`, which DOES have the applet (verified via `strings`). The builder's intent was always to use busybox2 via a symlink named `httpd`, not the smaller busybox.
2. **"The builder compiles its own busybox and the copy step is missing/broken."** — Not the case; no busybox build step exists. The builder relies on the busybox2 already present in NestDFUAttack's initramfs.
3. **"A separate httpd binary was supposed to ship in deps/."** — Not the case; `deps/` has no httpd binary, and the design only needs busybox2 to be present on the persistent rootfs.
4. **"Init script's `${BINDIR}/httpd` should have been `${BINDIR}/busybox httpd`."** — Not necessary. `BINDIR=/bin` and the symlink `/bin/httpd → /bin/busybox2` is functionally identical to invoking `busybox2 httpd` (busybox dispatches on argv[0]). The real bug is that the symlink's target isn't being copied in.

The actual root cause is a fifth one, narrower than any of the four: the cp of busybox2 was placed in the wrong conditional block when the nleapi feature was added in `e796765`. The earlier "Update bugs after testing" commit (`123595b`) cleaned up the shebang and removed a reference to a never-committed `install_httpd.sh`, but missed this.
